Планировщик задач
Описание проекта

Веб-сервер на Go, который работает как простой планировщик задач (TODO-лист). Сервер отдаёт готовый фронтенд из папки web и предоставляет REST API для работы с задачами. Данные хранятся в SQLite (файл scheduler.db).

Возможности:

добавление, просмотр, редактирование и удаление задач;
отметка задачи выполненной: разовая задача удаляется, повторяющаяся переносится на следующую дату;
повторяющиеся задачи с правилами d <число>, y, w <дни недели>, m <дни месяца> [<месяцы>];
поиск задач по тексту (заголовок и комментарий) и по дате в формате ДД.ММ.ГГГГ;
вход по паролю.

Основные маршруты API:

Маршрут	Методы	Назначение
/api/signin	POST	вход по паролю, возвращает JWT-токен
/api/nextdate	GET	вычисление следующей даты по правилу повторения
/api/task	POST, GET, PUT, DELETE	одна задача
/api/tasks	GET	список задач (до 50), параметр search
/api/task/done	POST	отметить задачу выполненной
Выполненные задания со звёздочкой
Аутентификация. Вход по паролю из переменной TODO_PASSWORD, токен JWT (HS256, срок жизни 8 часов) хранится в куке token. Если пароль не задан, авторизация отключена.
Поиск задач. Параметр search в /api/tasks: поиск по тексту и по дате.
Docker-образ. В корне проекта лежит Dockerfile.
Правила повторения w и m. Реализованы полностью: w со списком дней недели (1–7), m со списком дней месяца (1–31, -1, -2) и необязательным списком месяцев (1–12), например m 10,17 12,8,1. В tests/settings.go стоит FullNextDate = true.
Запуск локально

Нужен Go версии, указанной в go.mod.

Переменные окружения
Переменная	Значение по умолчанию	Назначение
TODO_PORT	7540	порт веб-сервера
TODO_DBFILE	scheduler.db в текущей папке	путь к файлу базы данных
TODO_PASSWORD	не задан	пароль; если пусто, вход не требуется

Файл .env программа сама не читает, переменные нужно передать при запуске. Пример файла .env (его можно использовать как шпаргалку или подключать через IDE или Docker):

dotenv
TODO_PORT=7540
TODO_DBFILE=./scheduler.db
TODO_PASSWORD=12345
Команды запуска

Linux / macOS / Git Bash:

TODO_PASSWORD=12345 go run .

Windows PowerShell:

powershell
$env:TODO_PASSWORD="12345"; go run .

Без пароля (вход отключён): просто go run ..

Адрес в браузере
http://localhost:7540

Если пароль задан, на первой странице нужно ввести его. Если пароль не задан, планировщик откроется сразу. База данных scheduler.db создаётся автоматически при первом запуске.

Запуск тестов

Тесты находятся в папке tests и обращаются к уже запущенному серверу.

Запустите сервер с паролем (см. выше), например с паролем 12345. Окно с сервером не закрывайте.
Получите токен в другом окне терминала. PowerShell:
powershell
   $r = Invoke-RestMethod -Method Post -Uri http://localhost:7540/api/signin -ContentType "application/json" -Body '{"password":"12345"}'
   $r.token

Linux / macOS / Git Bash:

   curl -X POST http://localhost:7540/api/signin -H "Content-Type: application/json" -d '{"password":"12345"}'

(в ответе нужна только строка из значения token) 3. Откройте tests/settings.go и вставьте токен в переменную Token. Остальные параметры:

go
   var Port = 7540
   var DBFile = "../scheduler.db"
   var FullNextDate = true
   var Search = true
   var Token = `сюда_вставьте_токен`
Port должен совпадать с портом сервера;
DBFile путь к базе, которую использует сервер, относительно папки tests;
FullNextDate = true, так как правила w и m реализованы полностью;
Search = true, так как поиск реализован;
Token токен, полученный на шаге 2. Он зависит от пароля: если сервер перезапущен с другим паролем, токен нужно получить заново. Токен действует 8 часов.
Запустите тесты:
   go test ./tests

Если пароль не задан (TODO_PASSWORD пуст), токен не нужен: оставьте переменную Token пустой.

Сборка и запуск через Docker
Сборка образа

Из корня проекта:

docker build -t todo-app .
Запуск контейнера

Контейнер подключается к базе данных SQLite на хосте: папка проекта (в которой лежит scheduler.db) монтируется в контейнер как /data. Если файла scheduler.db нет, он будет создан в этой папке.

Windows PowerShell (из папки проекта):

powershell
docker run -d --name todo -p 7540:7540 -e TODO_PASSWORD=12345 -e TODO_DBFILE=/data/scheduler.db -v "${PWD}:/data" todo-app

Linux / macOS / Git Bash (из папки проекта):

docker run -d --name todo -p 7540:7540 -e TODO_PASSWORD=12345 -e TODO_DBFILE=/data/scheduler.db -v "$(pwd):/data" todo-app

Пояснения:

-p 7540:7540 открывает порт; планировщик доступен по адресу http://localhost:7540;
-e TODO_PASSWORD=... задаёт пароль (в образ он намеренно не вшит; без этой переменной вход отключён);
-e TODO_DBFILE=/data/scheduler.db и -v ...:/data подключают базу данных с хоста.

Остановить и удалить контейнер:

docker rm -f todo

В образе заданы ENV TODO_PORT=7540 и ENV TODO_DBFILE=/data/scheduler.db, порт объявлен через EXPOSE 7540.
