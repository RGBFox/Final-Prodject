# Планировщик задач

Веб-приложение на Go для управления повседневными задачами. Позволяет планировать дела, задавать повторения и отмечать задачи выполненными. Данные сохраняются в SQLite, управление доступно через браузер.

## Возможности

- Создание, просмотр, редактирование и удаление задач.
- Список задач с сортировкой по дате и ограничением до 50 записей.
- Поиск по заголовку, комментарию и дате в формате `ДД.ММ.ГГГГ`.
- Повторения по дням, годам, дням недели и дням месяца.
- Завершение задачи: разовая удаляется, повторяющаяся переносится на следующую дату.
- Вход по одному паролю, без имени пользователя.

## Выполненные задания со звёздочкой

| Задание | Реализация |
| --- | --- |
| Расширенные правила повторения | `w` — список дней недели; `m` — список дней месяца и необязательный список месяцев |
| Поиск задач | Параметр `search`: поиск по тексту или дате |
| Аутентификация | Пароль из `TODO_PASSWORD`, JWT с подписью HS256 и сроком действия 8 часов |
| Настройка через окружение | Поддержка `TODO_PORT`, `TODO_DBFILE` и `TODO_PASSWORD` |
| Docker | Многоэтапная сборка приложения и подключение SQLite с хоста |

## Технологии

- **Go 1.26 или новее** — версия модуля указана в `go.mod`.
- **`net/http`** — HTTP-сервер и маршрутизация.
- **SQLite** и **`modernc.org/sqlite`** — хранение данных без CGO.
- **`github.com/golang-jwt/jwt/v5`** — создание и проверка JWT.
- **Docker** — сборка и запуск в контейнере.

## Структура проекта

| Путь | Назначение |
| --- | --- |
| `main.go` | Подготовка БД и запуск HTTP-сервера |
| `backend/database/` | Выбор файла БД, создание таблицы и индекса |
| `backend/rules/` | Расчёт следующей даты повторяющейся задачи |
| `backend/server/` | Обработчики API, валидация и аутентификация |
| `web/` | Готовый веб-интерфейс |
| `tests/` | Интеграционные тесты |
| `Dockerfile` | Инструкции сборки Docker-образа |

## Настройки

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `TODO_PORT` | `7540` | Порт HTTP-сервера |
| `TODO_DBFILE` | `scheduler.db` | Путь к файлу SQLite относительно рабочей директории сервера |
| `TODO_PASSWORD` | Не задана | Пароль для входа; пустое значение отключает аутентификацию |

Пример файла `.env`:

```dotenv
TODO_PORT=7540
TODO_DBFILE=./scheduler.db
TODO_PASSWORD=replace-with-a-strong-password
```

Замените пароль из примера своим. Не добавляйте файл с настоящим паролем в репозиторий.

> Программа не загружает `.env` автоматически. Передайте переменные через терминал, настройки IDE или параметры запуска Docker.

## Локальный запуск

Все команды выполняются из корня проекта — директории, где находятся `go.mod` и `main.go`.

### С паролем

**Linux / macOS / Git Bash:**

```bash
TODO_PASSWORD='replace-with-a-strong-password' go run .
```

**Windows PowerShell:**

```powershell
$env:TODO_PASSWORD = "replace-with-a-strong-password"
go run .
```

Откройте **[http://localhost:7540](http://localhost:7540)** и введите заданный пароль. Если вы изменили `TODO_PORT`, укажите соответствующий порт в адресе.

При отсутствии файла БД приложение создаст его вместе с таблицей `scheduler` и индексом по дате. Для завершения работы нажмите `Ctrl+C` в терминале сервера.

### Без пароля

При пустой или незаданной переменной `TODO_PASSWORD` вход не требуется.

**Linux / macOS / Git Bash:**

```bash
TODO_PASSWORD= go run .
```

**Windows PowerShell:**

```powershell
$env:TODO_PASSWORD = ""
go run .
```

## Запуск тестов

Тесты из `tests/` обращаются к уже запущенному серверу и напрямую к его базе данных. Сервер и тесты должны использовать один порт и один файл БД.

> **Тесты изменяют данные.** В частности, `TestTasks` очищает таблицу `scheduler`. Для проверки используйте отдельную копию проекта с тестовой БД или предварительно сохраните рабочую базу.

### Проверка без аутентификации

1. Укажите в `tests/settings.go` следующие значения:

   ```go
   var Port = 7540
   var DBFile = "../scheduler.db"
   var FullNextDate = true
   var Search = true
   var Token = ``
   ```

2. Запустите сервер без пароля по инструкции выше. При стандартных настройках он будет использовать файл `scheduler.db` в корне проекта.

3. Откройте второй терминал в корне проекта и запустите все тесты:

   ```bash
   go test -count=1 ./tests
   ```

Флаг `-count=1` отключает использование кэшированного результата тестов.

| Параметр | Что указать |
| --- | --- |
| `Port` | Порт запущенного сервера |
| `DBFile` | Путь к той же БД относительно директории `tests`; для стандартного запуска — `../scheduler.db` |
| `FullNextDate` | `true`, чтобы проверить расширенные правила `w` и `m` |
| `Search` | `true`, чтобы включить проверки поиска |
| `Token` | Пустая строка при отключённой аутентификации или свежий JWT при включённой |

Переменные окружения `TODO_PORT` и `TODO_DBFILE` переопределяют соответствующие настройки тестов. При использовании `TODO_DBFILE` в обоих терминалах удобнее указать одинаковый абсолютный путь: рабочие директории сервера и тестов различаются.

### Проверка с аутентификацией

Запустите сервер с паролем и получите токен. В запросе укажите тот же пароль, который передали серверу.

**Linux / macOS / Git Bash:**

```bash
curl -X POST http://localhost:7540/api/signin \
  -H 'Content-Type: application/json' \
  -d '{"password":"replace-with-a-strong-password"}'
```

**Windows PowerShell:**

```powershell
$response = Invoke-RestMethod `
  -Method Post `
  -Uri "http://localhost:7540/api/signin" `
  -ContentType "application/json" `
  -Body '{"password":"replace-with-a-strong-password"}'

$response.token
```

Скопируйте значение поля `token` в переменную `Token` файла `tests/settings.go` и выполните:

```bash
go test -count=1 ./tests
```

Тесты передают JWT в cookie с именем `token`. Срок действия токена — **8 часов**. После истечения срока или смены пароля получите новый токен. Перед публикацией проекта очистите `Token`.

Для отдельного теста:

```bash
go test -count=1 -run '^TestTasks$' ./tests
```

## Сборка и запуск через Docker

Нужен установленный и запущенный Docker. На Windows используйте Docker Desktop в режиме Linux-контейнеров.

### 1. Соберите образ

Из корня проекта:

```bash
docker build -t todo-app .
```

На первом этапе Dockerfile компилирует приложение с `CGO_ENABLED=0`. В итоговый образ копируются исполняемый файл и директория `web`.

В образе заданы `TODO_PORT=7540`, `TODO_DBFILE=/data/scheduler.db` и `EXPOSE 7540`. Пароль передаётся при запуске контейнера.

### 2. Запустите контейнер

Команды ниже подключают текущую папку проекта к `/data` внутри контейнера. Поэтому файл `scheduler.db` хранится на хосте и сохраняется после удаления контейнера. Если файла нет, приложение создаст его.

Перед запуском освободите порт `7540`, если на нём уже работает локальный сервер.

**Linux / macOS:**

```bash
docker run -d --name todo \
  -p 7540:7540 \
  -e TODO_PASSWORD='replace-with-a-strong-password' \
  -e TODO_DBFILE=/data/scheduler.db \
  -v "$(pwd):/data" \
  todo-app
```

**Windows PowerShell:**

```powershell
docker run -d --name todo `
  -p 7540:7540 `
  -e TODO_PASSWORD="replace-with-a-strong-password" `
  -e TODO_DBFILE=/data/scheduler.db `
  -v "${PWD}:/data" `
  todo-app
```

**Windows Git Bash:**

```bash
MSYS_NO_PATHCONV=1 docker run -d --name todo \
  -p 7540:7540 \
  -e TODO_PASSWORD='replace-with-a-strong-password' \
  -e TODO_DBFILE=/data/scheduler.db \
  -v "$(pwd -W):/data" \
  todo-app
```

В варианте для Git Bash `pwd -W` возвращает путь Windows, а `MSYS_NO_PATHCONV=1` отключает автоматическое преобразование путей в аргументах Docker.

Откройте **[http://localhost:7540](http://localhost:7540)** и введите пароль из команды запуска.

| Параметр | Назначение |
| --- | --- |
| `-d` | Запуск в фоновом режиме |
| `--name todo` | Имя контейнера |
| `-p 7540:7540` | Публикация порта контейнера на хосте |
| `-e TODO_PASSWORD=...` | Пароль для входа |
| `-e TODO_DBFILE=/data/scheduler.db` | Путь к БД внутри контейнера |
| `-v ...:/data` | Подключение папки хоста с файлом SQLite |

Для запуска без аутентификации уберите параметр `-e TODO_PASSWORD=...`.

### 3. Проверьте сохранение данных

1. Создайте задачу в браузере.
2. Удалите контейнер командой ниже.
3. Запустите его повторно с той же подключённой папкой.
4. Войдите в планировщик и убедитесь, что задача сохранилась.

Просмотр журнала сервера:

```bash
docker logs todo
```

Остановка и удаление контейнера:

```bash
docker rm -f todo
```

Эта команда не удаляет подключённый файл SQLite на хосте.

## Основные маршруты API

| Маршрут | Метод | Назначение |
| --- | --- | --- |
| `/api/signin` | `POST` | Вход по паролю, выдача JWT |
| `/api/nextdate` | `GET` | Расчёт следующей даты повторения |
| `/api/tasks` | `GET` | Получение списка задач и поиск |
| `/api/task` | `POST` | Добавление задачи |
| `/api/task?id=...` | `GET` | Получение одной задачи |
| `/api/task` | `PUT` | Обновление задачи; ID передаётся в JSON |
| `/api/task?id=...` | `DELETE` | Удаление задачи |
| `/api/task/done?id=...` | `POST` | Завершение задачи |

При включённой аутентификации операции с задачами требуют JWT в cookie `token`. Маршруты `/api/signin` и `/api/nextdate` доступны без токена.

В API и базе даты хранятся в формате `YYYYMMDD`, например `20261111`. Поиск по дате использует формат `ДД.ММ.ГГГГ`, например `11.11.2026`.

## Правила повторения

| Правило | Значение | Пример |
| --- | --- | --- |
| `d N` | Каждые N дней, от 1 до 400 | `d 7` |
| `y` | Ежегодно | `y` |
| `w дни` | В выбранные дни недели: 1 — понедельник, 7 — воскресенье | `w 1,3,5` |
| `m дни` | В выбранные дни каждого месяца | `m 1,15` |
| `m дни месяцы` | В выбранные дни указанных месяцев | `m 10,17 1,8,12` |
| `m -1` | В последний день каждого месяца | `m -1` |
| `m -2` | В предпоследний день каждого месяца | `m -2` |

Пустое поле `repeat` означает разовую задачу. Функция `NextDate` возвращает ближайшую подходящую дату строго позже исходной даты и текущего календарного дня.
